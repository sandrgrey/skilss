# Universal Project Builder v2.0

**Модульная инженерная система для OpenAI Codex и Claude Code.** Подходит для сайтов, 3D-витрин, веб-приложений, Telegram-ботов, API, мобильных проектов и автоматизации. Не является генератором приложений сама по себе: это набор инструкций, рабочих процессов, шаблонов и проверяемых примеров для coding-агента.

## Быстрый старт

1. Скопируйте **содержимое** этого каталога в корень нового проекта (или осторожно объедините с существующими `AGENTS.md` / `CLAUDE.md`, не перезаписывая их).
2. Откройте `PROJECT_BRIEF.md`, замените все значения `TODO` на информацию о проекте. Используйте `AUTO`, если стек должен подобрать агент. Не нужно активировать все модули.
3. Откройте папку проекта в Codex **или** Claude Code.
4. Дайте задачу: **«Изучи PROJECT_BRIEF.md, выполни discovery и blueprint, затем реализуй проект и проверь критерии приёмки. Не имитируй пройденные проверки»**.
5. Для аудита уже существующего репозитория переключите `MODE: AUDIT` в brief, агент не должен менять код без отдельного задания.

## Что куда загружается

- `AGENTS.md` — основные проектные инструкции для **Codex**, короткие, с явным маршрутом к модулям.
- `CLAUDE.md` — основные проектные инструкции для **Claude Code** и импорты базовых документов из `.ai/core/`.
- `.claude/skills/` — skills Claude Code: blueprint, cinematic-scene, project-audit.
- `.agents/skills/` — эквиваленты skills Codex с теми же общими материалами.
- `.ai/core/` — универсальные правила, выполняются всегда.
- `.ai/modules/` — предметные механизмы, читаются **только при необходимости**.
- `.ai/adapters/` — профиль под тип проекта.
- `.ai/templates/` — чеклисты и бланки.
- `.ai/references/` — проверяемая математика анимации и параметры, извлечённые из Water.pdf.
- `.ai/examples/` — примеры заполнения.
- `scripts/` — необязательная проверка комплекта (требуется Node.js ≥18).

## Матрица подключения модулей

| Тип задачи | Адаптер | Дополнительные модули |
|---|---|---|
| Промосайт / лендинг | `adapters/landing.md` | design-system; cinematic/video при необходимости |
| Магазин / SaaS | `adapters/fullstack.md` | design-system, backend-data, security |
| 3D-каталог | `adapters/landing.md` или fullstack | design-system, 3d; cinematic опционально |
| Telegram-бот | `adapters/telegram-bot.md` | backend-data, security |
| CLI / автоматика | `adapters/automation.md` | architecture, security |
| Mobile | `adapters/mobile.md` | architecture, design-system, backend-data по потребности |
| Аудит | core + project-audit skill | профиль проекта, никаких обязательных правок |

## Три правила совместимости

1. **Никогда не переносите фиксированный холст в обычный интерфейс автоматически**: width-locked холст — опциональный режим для специальных сцен.
2. **Не выбирайте React/Vite/Three.js глобально**: технологии определяются `PROJECT_BRIEF.md` и целевой платформой.
3. **Не копируйте временные asset URL из референса в готовый сайт**: медиа либо предоставлены пользователем, либо получены с подтверждёнными правами, либо используются разрешённые заменители.

## Здоровый процесс

`DISCOVERY → BLUEPRINT → BUILD → REVIEW → VALIDATE → DELIVERY`, при повторяющихся ошибках включается LoopGuard. При существенной новой информации обновляется blueprint, а не переписывается проект вслепую.

## Пример команд

```bash
node scripts/validate-kit.mjs
node --test .ai/references/motion-core.test.mjs
```

Это тесты **самого набора инструкций и математики**, а не тестирование будущего сгенерированного приложения.

## Происхождение

Идеи `fixed stage`, `SCROLL_VH=620`, `VIDEO_SEAM=0.5`, трёх групп параллакса, `span/ramp/lerp`, двух клипов с переходом и принципа координатных измерений взяты из пользовательского **Water.pdf / Marlin**. Детали и ограничения перечислены в `.ai/references/from-water.md`. Все архитектурные политики, полноценный аудит, безопасность, адаптеры и система skills — развитие, добавленное в v2.0. Сам оригинальный сайт, медиаресурсы и его полный исходный код в этот архив **не включены**.

## Статус

Данный комплект готов к использованию как инструкции для агента, но его эффективность нужно оценивать на реальных репозиториях. Его наличие само по себе не гарантирует правильную сборку пользовательского проекта.
